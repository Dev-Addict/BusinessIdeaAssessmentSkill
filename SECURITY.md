# Security policy

## Supported version

Security fixes are applied to the latest version on the default branch.

## Reporting

Use GitHub private vulnerability reporting when it is enabled for the
repository. Otherwise, contact the repository maintainer privately rather than
opening a public issue containing exploit details, secrets, personal data, or
confidential business information.

Include the affected file/version, reproduction steps, potential impact, and a
safe suggested fix when available.

## Scope

Relevant issues include unsafe external-action authorization, accidental secret
or personal-data disclosure, command injection in validation scripts, path
traversal, and instructions that could misrepresent unverified evidence as fact.

The skill does not require credentials or network services of its own. Generated
business assessments may contain sensitive commercial information; users should
store and share them according to their own access-control and retention needs.
